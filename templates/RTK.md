## 3. 章节写作工作流

### 3.1 每章一个独立聊天

- 每一章都应在一个新的聊天中完成（避免上下文污染、避免风格漂移）
- 用户开始写新章节时，主动提醒并建议新开聊天
- 用户明确要求继续当前聊天的也可以执行，但默认仍以"每章一个聊天"为标准流程

### 3.2 写作顺序（novel-write 已固化）

1. 读总纲、章节大纲、`前情梳理.md`
2. 读与本章直接相关的前文章节，至少回看上一章，必要时回看最近 2-3 章
3. 读相关人物档案和 `伏笔清单.md`
4. 必要时参考 `写作技巧/*.md`
5. 确认本章目标：剧情推进 / 情感推进 / 人物变化 / 是否需要埋伏笔 / 是否需要补一笔时代或世界设定
6. 生成章节初稿
7. 按下文 §4 做一轮去 AI 味润色
8. 输出润色后的定稿，保存为独立 Markdown 文件
9. 走 `novel-sync` 同步：`前情梳理.md` / `人物档案/*.md` / `伏笔清单.md` / `经典语录.md`

### 3.3 文件命名规范

```
{{书名}}-第X章-章名.md
```

## 4. 去 AI 味原则（写作铁律）

### 4.1 一个情绪瞬间只写一次

写完一个具象动作 / 场景之后，**禁止**再用一句内心独白复述这个动作 / 场景的"含义"。

**典型病灶（必删）：**

- "她忽然意识到……"
- "她忽然明白……"
- "她忽然发现，原来……"
- "她以为……可原来……"
- "这才是真正让她……的地方"
- "原来……才是最让人……的"
- "它更像 / 它其实是"

### 4.2 章节结尾去模板化

避免连续 4 章以上使用"事件结束 → 主角独处 → 想起旧事 → 用一句关于成长 / 时间 / 旧时光的感悟收尾"。

**可替换的章末结构：**

- 未完动作（一个被打断或刚开始的动作）
- 物件落定（一个具体物件最后的位置）
- 未发生的事（本可发生却没发生的瞬间）
- 跨场景叠加（突然进来的另一条线打断当前情绪）
- 群消息切断（不相干的信息打回日常）
- 对话未完（一句话还没说完，戛然而止）

全书最多保留 3 处"感悟性结尾"，给最重要的章节用。

### 4.3 高频套话黑名单

以下短语每章上限 **1 次**，最好 0 次。可按项目题材增减：

- 心跳漏了一拍 / 眼睛深邃如星空
- 岁月静好 / 青春散场 / 命运的齿轮
- 我不是那个意思 / 你根本不懂我
- 与此同时 / 值得一提的是 / 不得不说 / 总而言之
- {{项目专属黑名单 → 写作过程中自行追加}}

### 4.4 zh-novel-polish 的使用规范

`zh-novel-polish` 是 plugin 内置的定稿前最后一道工序，**强制执行**：

- 自动扫描八大叙事病灶（命名式情绪、长定语、"的"字过载、静态描写、模板连接词、章末感悟、对话说教化、视角越界）
- 按本文件 §4.1-4.3 的项目化规则匹配执行
- 输出对照修改 + 全章统计 + 全书级提醒

**不要**：

- 不要切换到一般中文 humanize / 营销 / 短视频 / KOL 文案类 skill 来润色小说——它们的目标不一致
- 不要让润色阶段改情节、改人物关系、改伏笔走向
- 不要把作者特意保留的风格标记当病灶删

## 5. 文风要求

### 5.1 总体风格

- 细腻，但不过度堆砌辞藻
- 有情绪，但不滥情
- 有节奏，但不刻意
- 有留白，但不空泛

### 5.2 表达要求

- 多写具体场景、动作、细节，不要只写抽象感受
- 少用空洞总结句、鸡汤句、万能抒情句
- 对话要符合人物身份和年龄感
- 题材专属生活细节要真实（按 RTK §1 题材自检）

### 5.3 感情线要求（若题材涉及感情线）

{{按题材生成。参考举例（请按本项目改写）：
- 校园青春：从相识/重逢开始，慢慢靠近、误会、错过、沉默、释怀；不写一见钟情；初期心动靠"被准确看见"
- 都市言情：成年人的克制、试探、确认；不写工业糖精
- 武侠/历史：感情服从情节大势，不在国仇家恨里硬塞甜宠
- 悬疑：感情线不能压过主线悬念；用感情揭示线索
}}

### 5.4 时代 / 世界线要求

故事要带出**{{题材标签}}**应有的时代或世界底色，但不要写成新闻报道 / 设定说明书。

- 时代 / 世界变化优先通过人物日常去体现
- 与人物成长绑定，写成"他们怎么在变化中长大"，而不是生硬交代背景
- 每章不必专门点题，但全书推进时要持续存在这条底色

## 6. 连续性检查清单（novel-auditor 会按此核查）

每次写新章节前后，至少检查：

- [ ] 人物关系是否与前文一致
- [ ] 时间线是否连贯
- [ ] 主要感情/主线推进速度是否合理（不过快、不过慢）
- [ ] 多条线（主线 / 情感线 / 成长线 / 支线）是否同步推进
- [ ] 是否和总纲、章纲冲突
- [ ] 是否出现重复桥段或重复抒情
- [ ] 是否已经参考 `前情梳理.md` / 相关人物档案 / `伏笔清单.md`
- [ ] 新写内容是否延续人物既有说话方式和行为习惯
- [ ] 是否有必要补一笔题材专属底色（时代 / 世界 / 行业），并且补得自然

## 7. 人物档案规则

每个重要人物都在 `人物档案/` 目录下有单独文档。

每份人物档案至少包含：

- 基础身份与角色功能
- 性格、气质、内在驱动力
- 说话方式与常见表达习惯
- 已发生的重要事件（**只写正文已落地的**）
- 当前与其他人物的关系状态
- 当前困境、隐性情绪、未解决问题
- 相关伏笔或待回收信息

更新原则：

- 只记录正文里已经写出来的内容，**不能把未来剧情当成既成事实写进去**
- 已知设定和未来章纲可以写进"预设信息"或"待展开方向"，但要和已发生事件分开
- 新人物首次正式出场后，尽快补全说话方式和第一印象

## 8. 伏笔规则

- 偶尔用伏笔，但不要为了伏笔而伏笔
- 伏笔以轻、自然、能回收为原则
- 同一阶段不要连续堆太多明显伏笔
- 每埋一个较明确的伏笔，都要在 `伏笔清单.md` 里留痕
- 已回收的伏笔要标注在哪一章回收，避免重复使用
- 超过 8 章未回收的伏笔，`novel-sync` 会自动提醒

## 9. 每章最低交付标准

- 有明确的场景中心
- 有至少一个关系变化点
- 有至少一个人物内心变化点
- 有结尾钩子或余味，能自然接到下一章
- 定稿必须经过一轮去 AI 味润色
- 写完后必须同步更新前情梳理、人物档案和伏笔清单
- 如果本章出现了真正有留下价值的句子，要同步更新 `经典语录.md`

## 10. 非章节任务

如果用户做的是以下任务，**不必强行新开聊天**：

- 修改总纲
- 修改章节大纲
- 补人物小传
- 调整时间线
- 总结前文问题
- 做设定表
- 跑审稿（`novel-review`）

正式写"第 X 章正文"时，默认仍遵循"一章一个新聊天"的规则。
